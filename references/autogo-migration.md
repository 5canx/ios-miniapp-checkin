# AutoGo 华硕迁移依据（2026-11-19）

来源：awesomeProject1/common/wxinit.go 的 searchMini、pasteToSearchBox、TapText，以及 minicode/asus.go。以源码实际调用为准，不把全部步骤描述成固定坐标。

| 动作 | 原 AutoGo 实现 | 等待 | AutoDam 迁移要求 |
| --- | --- | --- | --- |
| 打开微信 | app.Launch | 3500 ms | 已确认前台时复用会话 |
| 打开搜索 | TapText 搜索；失败才点区域中心 (1154,225) px | 1200 ms | 旧右上角点在当前消息页可能是加号；使用已验证的可见搜索栏点 |
| 小程序分类 | uiacc.TextContains 小程序 → obj.Click | 1200 ms | 没有原固定坐标。当前 MCP 坐标触摸无转场，须核对控件动作与触摸执行差异，不能认定只是 OCR |
| 输入查询 | 找 Editable 框 → 长按1200ms → 全选/粘贴；菜单限区 OCR | 长按后1000ms；全选后600ms；粘贴后800ms；步骤后800ms | 复用剪贴板替换与旧内容清理，不能默认为直接输入完全等价 |
| 提交搜索 | motion.KeyAction(84) 回车 | 2000 ms | 对应 MCP 已有 press_key enter；不是固定点右上角 |
| 打开结果 | 区域中心 (604,603) px，Go 整数除法 | 3000 ms | 折算 (201.333,201) pt；搜索卡动态，需确认目标身份再用 |
| 关闭 | (1197,207) px | 2000 ms | (399,69) pt；保留退出状态确认 |

坐标基准1284×2778像素，当前手机428×926屏幕点、倍率3。AutoGo Sx/Sy 输入基准像素；MCP tap_screen 输入屏幕点，不能直接复制像素值。

当前 minicode/asus.go 的 (1146,2630) 已是上一轮从 AutoDam 迁入的点位，不能再循环引用它作为“旧 AutoGo 独立验证”的证据。原来的我的区域为 (1100,2597)-(1199,2655)，区域中心仅是回退点，不等于每次实际命中的控件坐标。

当前结论：AutoGo 的正常导航没有逐步全屏 OCR，但包含原生控件动作和粘贴菜单 OCR。AutoDam 0.3.6 重跑在分类点击后停止，OCR能返回同一页面；触摸是否生效与微信响应尚未查明。此表是迁移依据，未声称新的完整等价实现已安装或验收。
