# 固定坐标优先

正常路径：读取已验证流程与坐标 → 核对入口/设备几何 → 坐标点击或滑动 + 已测等待 → 在登录、业务结果及退出边界读取状态。仅异常、布局变化、未知弹窗或结果不符时取样修复；不每次抓树、全屏 OCR 或截图。

[微信与华硕坐标](baselines/coordinates-wechat-asus.json) 来自同一真实成功运行的动作边。包括搜索、分类、提交、我的及关闭。参考设备 428×926 pt @3（1284×2778 px），竖屏。搜索结果位置是动态数据，不能把上次结果卡坐标当永久入口。登录仍复用 [登录流程](login-workflow.md)，现有有效会话不重登。

## AutoDam 0.3.6

已支持的 tap 块使用 x/y + reference_width/reference_height；新增 reference_scale 表示参考坐标每屏幕点的单位数，同时约束当前逻辑尺寸。截图选点自动保存这三项。例：参考像素 1284×2778、倍率 3 对应 428×926 pt；从原生录制得到的屏幕点用 428×926、倍率 1。比例/方向不一致即停；新记录严格绑定逻辑尺寸，缩放改变时重新校准。旧 coordinate_scale 块仍兼容，但没有完整布局绑定，应重新取点。

固定 tap / scroll 不调用 get_ui_elements 或 ocr_screen；只核对前台与几何。原生小程序导航复用上表已验证坐标；搜索卡匹配、登录和最终个人中心/签到回执仍做必要识别。每步日志 device_tools 记录调用次数和耗时，可用来定位剩余慢点。

已从当前设备 tools/list 验证 ocr_screen 支持屏幕点 region={x,y,width,height}。0.3.6 的文字块有 region 时传实际裁剪区域；首次协商缓存能力，旧 MCP 未提供 region 时退回全屏识别后筛选。局部 OCR 不冒充完整页面缓存。动态字段尽量合并同一区域读取。AutoGo 使用 OcrInBounds 的区域入参。

## 录制与知识更新

learn 自动生成私有 coordinates.json、页面图和标准坐标功能块。手工标注不是自动捕获触摸；没有标注则报告缺动作，未测等待保留 null。候选 verified=false，需部署真机回放和检查终点后才提升为已验证。每条知识包含页面名、入口、顺序、点/滑动、等待、返回/关闭、App/小程序、尺寸、方向、倍率、验证范围和证据。

页面截图、完整 OCR、账户和日志只保存在手机或电脑私有目录。GitHub 只同步脱敏规则及上述非个人坐标；不发布账户信息。执行 succeeded 只代表功能块完成，签到仍需要当天已签到状态或发奖/流水证据。
