# 连续任务、区域 OCR 与通知（0.4.1）

先 `discover` 确认已安装版本，再 `read` 已有任务。主机脚本从 Monorepo 的 `host/autodam_link` 维护，Skill 的 `scripts` 是兼容映射；公开导出时复制真实脚本，不发布指向私有仓库的符号链接。

## 连续运行

手机任务页右上角「连续运行」按选择顺序建立队列；也可通过控制桥调用：

```json
{"operation":"batch_start","arguments":{"flow_ids":["autodam-asus-task","autodam-storm-task"],"timeout_seconds":300}}
```

- `batch` 返回队列状态和每项结果，不返回队列保存的配置快照。
- `batch_resume` 继续暂停队列的剩余任务；不会重新执行失败项。
- `batch_skip` 跳过尚未开始的下一项；`batch_stop` 停止当前所属批次和剩余项。
- `batch_retry` 只允许尚未执行任何步骤、未发送设备操作的失败项。中断或已经操作过的任务必须先检查业务证据，不能自动重放。
- 单个运行继续使用 `pause` / `resume` / `stop` 和实际 `run_id`。暂停不计入批次任务执行时限；正在执行的设备调用仍受自己的请求超时约束，停止不是瞬时强杀。
- 正常步骤完成不等于新签到。`business_outcome` 单独记录 `already_signed`、`new_signin_verified`、`verified_observed` 或 `unverified`。
- 小程序任务先保存回执，再核验关闭到微信首页/搜索入口。下一项建立新的执行器及 OCR 缓存，重新判断页面，不延用前一项页面状态。失败停止队列，保留现场。
- 服务重启将正在执行项标记为中断并暂停队列；不会自动重复不确定的签到或提交。

`events` 支持 `run_id` 和 `after_sequence`，返回 `events`、`cursor`；每次运行最多保留最近 500 个状态事件。`history` 返回最近运行。日志、页面文本和账户回执自动回传到本机私有目录，不同步到公开 Git。

## 只在必要时 OCR

固定动作使用已有页面、几何与点位。读取动态数据或核对关键页面时优先区域 OCR；区域缺少必要标题才补充一次全屏读取。已确认屏幕没有发生操作、缓存未过期且范围覆盖目标时复用 OCR；输入、点击、滑动和不确定操作会使缓存失效。不同区域不能冒充全屏观察。

区域使用逻辑点；原始 AutoGo 点位为 1284×2778 参考像素，两者不可混用。原生任务区域按设备尺寸转换，账户字段已使用「积分」「账户余额」等标签相对位置读取；不把金额附近任意数字当余额。动态布局缺少唯一标签时应停下来重新校准，不盲目平移点击点。

默认仍是外部 iOS MCP 的 PP-OCRv5 Mobile / ONNX Runtime CPU。可选 `run` 参数 `ocr_backend: "ncnn"` 仅在该次请求启用 AutoDam 自带候选的区域识别；全屏仍经 MCP。候选进程异常则本次连接回退，不循环重启。候选全屏识别曾导致微信搜索页 UNKNOWN，不应作为稳定默认后端。

## 通知

手机独立「通知」页提供 Telegram Bot 和 WxPusher，分别配置启用、凭据、接收目标、事件、消息模板和测试消息。凭据及接收目标存入共享钥匙串，设备独有、首次解锁后可用；不写普通配置文件、日志或仓库。

Telegram 使用 `sendMessage`，目标是 Chat ID 或频道用户名；WxPusher 标准 API 使用 appToken 和 UID，多个 UID 以逗号分隔。默认模板只使用任务名称、运行状态、耗时和业务核验状态，不上传账户数值、截图或原始错误。

接口受理不是对方已读。超时或中断后的发送结果可能不确定，系统不自动重发；本地投递记录只存渠道、事件与结果。实际凭据由用户在手机填写，未经真实发送不能标记通知送达已验证。
