# 端到端验收

| 用例 | 通过条件 |
|---|---|
| 从宿主真实入口进入小程序 | 四个可见导航步骤依次达成，目标品牌与独有控件吻合 |
| 当日首次签到 | 签到前能证实未签，必要业务动作一次，真实回执确认，按实际可见范围记录奖项和前后余额 |
| 当日已签或同日重跑 | 进入并读到当天独立回执，未重复签到或领取 |
| 任务只要求个人中心 | 品牌和个人中心页面至少两组独立锚点；收口为 profile_verified |
| 结果遮罩与关闭 | 先读确认信息，再关闭正确层级；回到期望页面，退出不会丢失业务证据 |
| 权限／隐私／人机验证 | 流程停在需用户决定的步骤；处理后能从确认页面恢复 |
| 异步、断线和不完整流水 | 只做有界恢复和只读核查；证据不足时返回未确认 |
| 部署验收 | 重新打开编辑器，导入的步骤、样本与间隔正确，原流程、名称、定时和手工校准仍可用；设备完成一次新流程手动测试 |
| 日志 | 记录当地日期、实际验收步骤、数据来源、私有证据位置与未显示字段。执行器测试终态与业务事实分别列出 |

在报告中注明每项发生于本机静态检查、私有设备读屏、首次业务动作或同日复跑；写明哪些场景当天无法再复现，下一次待观察。任何阈值、规则、活动说明或流程测试绿色标记都不能单独证明新增奖励。

## 已验证的组合

在 autodam 0.2.5、微信 8.0.80、iOS 15.6.1 和 iOS MCP 1.2.8 上，从手机编辑页「立即运行」完成了下列流程。基线保留各自实际运行的功能块摘要。模板升级后，设备保留的单步校准参数可能使摘要与出厂模板不同。

| 流程 | 已验证的终点 | 基线 |
| --- | --- | --- |
| 华硕商城（7 步） | 个人中心的品牌与账户栏目 | [华硕](baselines/asus.json) |
| 影视飓风Club（11 步） | 当日签到日历回执 | [影视飓风](baselines/storm.json) |
| 安慕希（9 步） | 对应任务行完成，关闭小程序后返回微信 | [安慕希](baselines/yogurt.json) |
| 七彩虹商城（9 步） | 当日同一笔签到积分收入流水 | [七彩虹](baselines/colorful.json) |

首次签到和领奖通过真机操作观察，随后由安装版读取已有的当日回执。新账户、不同活动版本以及第二天实际重新发奖，仍按当次页面和流水验收。相关账户数值、截图及测试原始日志留在设备本地。
